## 二、核心结论

**✅ 机制有效** —— 三条独立证据：

1. **系统确实学会了**：画像与真实兴趣的余弦对齐度 0.514 → 峰值 **0.698**（末轮 0.658）。画像不是摆设，它在向真兴趣收敛。
2. **推荐随之变准**：兴趣匹配度在第 11 轮达到峰值 **0.347**，中段均值 0.243，命中率峰值 **0.7**（即 10 张里有 7 张命中兴趣方向）；而冷启动前 3 轮只有 0.103。
3. **标签空间携带可学习的兴趣信号**：用卡片标签特征预测「这个人类会不会喜欢」的逻辑回归，留出集 **AUC = 0.781**、准确率 0.775（正例率 0.6）。换句话说：机制依赖的标签表示是**预测有效的**，不是噪声。

## 四、预测有效性（逻辑回归，numpy 手写）

- 样本：**200** 张卡片（正例率 0.6）
- 训练准确率 0.856 / **留出集准确率 0.775** / **留出集 AUC 0.781**
- 模型学到的高权重维度：`python` +1.43, `llm` +1.34, `voice` +1.27, `audio` +1.22, `agent` +1.11, `tts` +1.04
- 模型学到的负权重维度：`cloud` -0.49, `database` -0.42, `education` -0.27, `quantization` +0.00

> 注意：模型**没有被告知**数字人类的兴趣表，它只看到卡片标签和「人类喜不喜欢」的结果。它自己学到 `python / llm / voice / audio / agent / tts` 为正 —— 而这正是实验设定的兴趣；把 `database / cloud / education` 学成负 —— 也正是设定里最弱的维度。

## 五、发现与限制

- **中后段匹配度回落**（峰值 0.347 → 末段 0.099）不是机制失效，而是**候选池枯竭**：本实验语料库只有 258 个仓库，数字人类在 11 轮里就把高匹配的仓库刷完/互动完了（互动过的会进冷却期，短期内不再推），补货只能退而求其次。
- 这恰好验证了系统设计的另一半：**队列见底要能定向补货**。生产环境里对应的是 Scrapling 爬虫按画像方向抓新仓库（`POST /api/queue/crawl`），语料库越大，学习曲线的高位平台越长。
- 另一个可做的改进：把「冷启动前 2 轮」的补货查询也加上画像方向，可以让曲线更早抬起来。

## 六、怎么复现

```bash
# 1) 起后端（另开一个终端）
cd backend && python app.py
# 2) 跑实验（默认 12 轮；独立用户 id=2）
python backend/jobs/ml_simulate.py --rounds 20
# 3) 用真实用户的 GitHub 实证圈当兴趣（需先登录并同步）
python backend/jobs/ml_simulate.py --interest user --rounds 12
# 4) 只重生成本报告（不重跑实验）
python backend/jobs/ml_simulate.py --report-only
```

---

*指标口径：**兴趣匹配度** = 卡片标签向量与真实兴趣向量的加权余弦；
**命中率** = 匹配度 ≥0.25 的卡片占比；**画像对齐度** = 系统学到的画像与真实兴趣的余弦相似度；
**AUC** = 逻辑回归在 20% 留出集上区分「喜欢/不喜欢」的能力（0.5 = 随机）。*
